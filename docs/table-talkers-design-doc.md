# Table Talkers — 원탁 대화 시뮬레이터 설계 문서 (v0.2)

> 3D 공간에서 원탁에 둘러앉아 실시간으로 "대화"하는 데 집중한 소셜 시뮬레이터.
> 플랫폼: PC / Steam. 게임 메커닉 없음. 핵심 가치 = **존재감 있는 실시간 대화**.

### 이번 버전 변경점 (v0.1 → v0.2)
- **방 모델 확정:** 초대제/비공개 우선. 공개 발견은 이후. (§4)
- **수익화 추가:** 무료 F2P 베이스 + Pro Steam DLC(원타임·영구) + 코스메틱. 호스트-페이 → 방 전체 격상. (§5)
- **§12 정정:** "AI 참가자" → **공유 협업 표면**(화면공유·공유 문서·공유 브라우저). (§20)
- **v1 필수 승격:** 오디오 품질(AEC/노이즈/AGC), 온보딩, 기본 텍스트 채팅, 법무 문서, 신고 수신 백엔드, 애널리틱스, 버전 동기화.
- 백엔드 현실·리텐션·컴플라이언스 섹션 신설.

---

## 1. 제품 원칙

애매한 결정은 항상 여기로 돌아온다.

1. **대화가 제품이다.** 스코어·승패·미니게임 없음. 같이 앉아 있는 느낌만 판다.
2. **존재감 > 그래픽 충실도.** "저 사람이 지금 나를 보고 있다 / 웃었다 / 끼어들려 한다"를 판다.
3. **지연이 최우선 지표다.** mouth-to-ear 지연이 대화 자연스러움을 결정한다. 프레임률보다 중요.
4. **입장은 마찰 0이자 무료다.** 소셜 제품의 가치는 네트워크에서 나온다 — 내 사람들이 방에 있어야 가치가 있다. 입장을 막으면 제품이 죽는다.
5. **가치를 만드는 호스트에게 과금한다.** 결제는 원타임 우선. 방을 크고 좋게 만드는 사람에게만 돈을 받는다.
6. **초대한 사람하고만 대화한다(우선).** 낯선 사람 공개 음성방의 위험을 기본적으로 회피한다.
7. **참가자·방을 하드코딩하지 않는다.** 좌석을 채우는 주체, 방에 놓이는 오브젝트를 추상화해 미래 확장(공유 표면 등)의 문을 열어둔다.

## 2. 핵심 경험 (Core Loop)

```
앱 실행
  → 아바타/닉네임 선택 (최초 1회, 이후 스킵)
  → 마이크 설정/테스트 (최초 1회)
  → 방 생성  또는  친구 초대/링크/코드로 입장
  → 원탁에 착석 (1인칭 시점)
  → 대화 (고개 돌림 · 시선 · 립싱크 · 이모트 · 음성)
  → 나가기 / 방 유지
```

이 흐름을 매끄럽게 만드는 것이 개발의 8할.

## 4. 방 모델 — 초대제 우선

방을 공개로 열지 초대제로 갈지는 기능이 아니라 제품 뼈대다. 모더레이션 부담·안전·콜드스타트가 전부 여기서 갈린다.

- **v1 = 초대제/비공개.** 친구 초대·링크·코드로만 입장. "내 사람들과 대화" 컨셉과 일치.
- **효과:** 낯선 사람 공개 음성방의 위험(괴롭힘·레이드·미성년자 안전)이 대부분 사라지고, 신고/차단 파이프라인이 가벼워지며, 컴플라이언스·연령등급 부담이 완화된다.
- **공개 발견(discovery)·커뮤니티 방 = 이후.** 모더레이션이 견고해진 뒤에 얹는다.

## 5. 비즈니스 모델 / 수익화

**원칙:** 입장 무료(§1-4) · 호스트에게 과금(§1-5) · **원타임 우선.**

**구현: 무료 F2P 베이스 게임 + Pro는 Steam DLC(원타임·영구).**
- 비결제자 = 베이스 클라이언트로 무료 입장(게스트 패스). **완전한 대화 경험은 무료.**
- 호스트가 Pro DLC 소유 시 → **방 전체**가 격상(정원 ~12명, 무제한 시간, 예약/링크 초대, 아바타·방 커스터마이즈). 그룹에 결제자 한 명이면 충분.
- Steam이 DLC 소유권을 자동 동기화 → 자체 라이선스 서버가 거의 불필요.
- **코스메틱**(아바타 아이템·방 테마) = 추가 DLC 팩 또는 Steam 마이크로트랜잭션. 무료 유저도 구매 → 코어를 막지 않고 지속 매출. 3D 소셜의 Steam-네이티브 수익원(VRChat·Rec Room이 실제로 여기서 번다).
- **Team/Enterprise = 이후.** 시트 기반, 협업 표면 기능과 함께. 지금 범위 아님.

**이점**
- Steam이 merchant of record → 결제·부가세(VAT)·환불을 전부 대행. 자체 빌링 불필요(원타임 + Steam-first의 핵심 이점).
- 대화 앱이라 치트할 게 없어 안티치트 불필요.

**수수료 / 스테이징**
- Valve 30% (누적 매출 $10M 초과분 25%, $50M 초과분 20%). 훗날 SaaS로 커지면 웹 다이렉트 결제로 수수료 절감 옵션.
- 출시 = 베이스 + Pro DLC 하나 + 코스메틱 팩. **v1에 3단 SaaS 결제 만들지 말 것.** 사람들이 실제로 뭐에 돈 쓰는지 보고 티어를 늘린다. 구독은 반복 사용 툴로 자리잡은 뒤. Enterprise는 협업 기능 붙는 시점.

## 7. 아키텍처 개요

```
[클라이언트 A · 호스트]      [클라이언트 B, C … · 게스트]
        \                          /
         \        (fan-out)       /
   ┌──────────────────────┐   ┌──────────────────────┐
   │  Steam 인프라 (무료)   │   │     음성 서비스        │
   │  · Lobby (방/매칭)     │   │  MVP: Steam Voice     │
   │  · Relay (NAT/P2P 중계)│   │  v1 : ODIN / Vivox    │
   └──────────────────────┘   │       (공간 음성)      │
                              └──────────────────────┘
        (별도: 신고 수신·애널리틱스·크래시 → 경량 백엔드)
```

- **호스트 방식(host-authoritative / listen server).** 방마다 한 명이 호스트, 나머지가 게스트. 전용 서버 없음.
- **두 개의 독립 경로.** 상태 동기화(NGO/FishNet → Steam Relay) / 음성(음성 서비스 채널).
- **참가자 추상화.** 서버 로직은 좌석을 `IParticipant`로만 다룬다. 지금은 `HumanParticipant`만. 이 한 가지가 미래 확장(에이전트/봇 등)을 저비용으로 만든다.
- **방 오브젝트 추상화.** 방은 아바타 + 테이블 외에 **"공유 표면 오브젝트"**(화면/보드/문서 패널)를 담고 동기화할 여지를 남긴다. 지금은 없지만 하드코딩하지 않는다(§20).

### 동기화하는 상태
- 좌석 인덱스 (누가 어느 자리)
- **시선/헤드 오리엔테이션** (카메라 forward 또는 head yaw/pitch) ← 존재감 핵심
- 상체·손 트랜스폼 (선택, lean·제스처용)
- 애니메이션 상태 (idle / talking / emote id)
- 발화 여부 (mic active bool)
- 아바타 외형 데이터 (입장 시 1회 + 변경 시)
- 이모트 이벤트 (RPC, 일회성)

자리 이동이 없어 대역폭이 낮다. 트랜스폼 10~20Hz 보간, 이모트/외형은 이벤트/상태.

## 8. 대화 존재감 상세 (이 제품의 차별점)

> 여기가 잘 안 되면 나머지가 완벽해도 제품이 죽는다. 우선순위 순.

1. **헤드 오리엔테이션 / 시선 (최우선).** 카메라 방향을 공유 → 아바타 머리가 그쪽을 향함. "누가 누구를 보는지"가 방에 드러남. 옵션: 발화자 자동 look-at, 눈동자 추적.
2. **립싱크.** MVP=마이크 진폭→턱 개폐. v1=uLipSync/OVR LipSync viseme.
3. **발화 표시.** 마이크 활성 시 이름표/아바타 은은한 하이라이트. 0.1초 안에 인지.
4. **턴테이킹 보조.** "손 들기" 이모트 + 발화 대기 표시. 동시 발화 시각 정리(게임 아님, 편의).
5. **비언어(바디랭귀지=콘텐츠).** 최소: 끄덕임 / 웃음 / 손 들기 / 엄지 / 박수.
6. **공간 오디오.** 아바타 방향·거리에서 목소리 → 다자 대화 추적 쉬움, 존재감 급상승. MVP 이후 최우선 폴리시.
7. **좌석 & 카메라.** 착석 1인칭, 고개 자유 회전, 살짝 lean. 자리 이동 없음. 원탁 반경·의자 간격·착석 높이 튜닝.

**지연 예산:** 목표 mouth-to-ear ≈ **150–200ms 이하.** 초과 시 대화가 무전기처럼 됨. 이 수치가 음성 기술·서버 리전을 좌우.

## 9. 네트워킹 상세
- **모델:** host-authoritative listen server. 호스트가 진실 소스.
- **전송:** Steam Relay(무료 NAT 통과·중계).
- **틱레이트:** 트랜스폼 10~20Hz + 클라이언트 보간.
- **호스트 마이그레이션(v1):** 호스트 이탈 시 권한 이양, 세션 유지(숨은 공수 큼).
- **재접속:** 일시 끊김 후 같은 좌석 복귀, 상태 재동기화.
- **버전 동기화(v1):** P2P라 같은 버전끼리만 접속 → 강제 업데이트/버전 게이트 전략 필요.
- **정원:** 방당 4~12명(그 이상은 대화 성립 안 됨, 설계 상한).

## 10. 아바타 & 아트
- MVP: 스타일라이즈드 프리셋 3~6종 + 색상 → v1: 커스터마이즈/Ready Player Me.
- 본 구조는 립싱크(입/턱)·헤드·상체 IK 지원하도록 통일.
- 환경: 방 하나로 시작, "무드"(코지 라운지/회의실/카페)가 대화 톤 좌우 → 조명·재질 투자. 스코프 작게, 완성도 높게.
- 이름표: 항상 표시 옵션 + 발화 강조.

## 11. 음성 상세
- **MVP: Steam 내장 음성**(무료·단순·즉시, 비공간).
- **v1: 공간 음성 전환** — ODIN(엔진 레벨 3D·근접·오클루전, 무료 시작/€49.90월~/PCU €0.29~, 음성에 데이터 동봉 가능) 또는 Vivox(UGS·엔진 비종속·3D·통합 빠름, 요금 최신 확인).
- **오디오 품질(v1 필수, 선택 아님):** 에코 캔슬(AEC)·노이즈 억제·자동 게인(AGC). "누구 마이크 하울링/시끄러움"이 실사용 불만 1위. 여기 품질 = 제품 품질.
- **필수 컨트롤:** 마이크 선택, PTT/음성감지 토글, 개인볼륨, 뮤트, 마이크 테스트.
- 코덱 Opus.

---

## 12. 텍스트 채팅 & 접근성 (v1)
- **기본 텍스트 채팅:** 링크 공유·조용한 참여·시끄러운 환경 대응. 대화 제품이라도 텍스트 한 줄은 있는 게 낫다.
- **접근성(이후 우선):** 실시간 자막/STT — 청각 접근성 + 실용성.

---

## 13. 온보딩 (v1)
- 첫 실행: 마이크 권한 요청 → 장치 선택 → **마이크 테스트** → "다들 들려요?" 체크.
- 이탈이 가장 큰 지점. 여기서 무너지면 뒤가 다 무의미.

---

## 14. 안전 / 모더레이션 (출시 필수)
- 뮤트(개별), 개인 볼륨 조절, **차단(block)**(이후 상호 비노출/비가청), **신고(report)**.
- **신고 수신 백엔드(v1):** "신고 버튼"만 있고 뒤가 없으면 무의미 → 최소한의 수신 큐 필요(§18).
- 호스트 권한: 킥, 방 잠금, 정원 제한.
- **초대제(§4)가 안전 표면을 근본적으로 줄인다** — 모더레이션의 1차 방어선.
- (이후) 서버측 로깅/자동 모더레이션.

---

## 15. 법무 / 컴플라이언스 (v1 필수)
- **개인정보처리방침 · 이용약관 · EULA** — Steam 출시 필수.
- 음성 = 개인정보(국내 PIPA·EU GDPR) → 처리 근거·보관·삭제 정책 필요.
- **녹화·전사 = 이후.** 동의·녹화 중 고지·보관정책이 붙는 가장 무거운 컴플라이언스 항목 → v1 제외.
- 연령 등급(GRAC 등)·미성년자 정책 — 초대제로 대부분 완화.

## 16. Steam 통합
- **Lobbies**(방/매칭·초대), **Relay**(전송·무료), **내장 음성**(MVP).
- **DLC**(원타임 Pro) + **마이크로트랜잭션/인벤토리**(코스메틱).
- **Rich Presence**("○○의 원탁에서 대화 중") → 친구 합류 → 소셜 확산.
- 친구 초대/초대 링크(핵심 유입), 도전과제, 상점 페이지, 트레일러.
- Steam Direct 앱당 1회 $100(회수 가능).

## 17. 백엔드 현실 & 운영 (v1)
"서버비 0"은 **실시간 전송 한정**이다. 아래는 어딘가 경량 백엔드로 생긴다(비용은 미미):
- **신고 수신 큐**(§14), **애널리틱스**(세션 길이·방 크기·크래시·Pro 전환 퍼널), **리모트 컨피그**, **크래시 리포트**.
- 측정 못 하면 개선 못 한다. Pro 전환 퍼널은 원타임 모델에서도 필수 지표.

## 18. 리텐션 / 콜드스타트
소셜 앱은 열었을 때 아무도 없으면 죽는다. 원타임이라 반복 매출 압박은 없어도, 입소문·코스메틱을 위해 리텐션 필요.
- v1: 친구 접속 표시/알림, 초대 링크(핵심 루프).
- 이후: 예약 방, 상시 방(persistent).

## 19. 플랫폼 / 사양
- 데스크톱(Windows) 우선. 저사양 타깃(무겁게 만들 이유 없음).
- **VR = 자연스러운 미래 플랫폼**("테이블에 앉는" 존재감). 본 구조를 VR로 못 넓히게만 막지 않는다.

## 20. 향후 확장 (지금 구현 안 함, 문만 열어둠)

**공유 협업 표면 (핵심 미래 방향).** 대화하다가 방 안에서 화면 공유·공유 문서·공유 브라우저를 같이 보는 협업. *(이전 문서의 "AI 참가자"는 오해였고 이걸로 정정.)*
- **아키텍처 대비:** 방을 "아바타 + 테이블"로 하드코딩하지 말 것(§7). 방이 참석자 외 **공유 표면 오브젝트**(화면/보드/문서 패널)를 담고 동기화할 여지를 남기면, 훗날 큰 리팩터 없이 얹힌다.
- 이 방향이 Gather·Teamflow류 3D 협업 공간으로의 확장이자 **Team/Enterprise 티어의 근거**(§5).

**기타 미래:** Team/Enterprise(SSO·관리자·상시 브랜드 공간), 공개 발견/커뮤니티, 녹화·전사, 구독, VR.

## 22. 리스크 / 숨은 공수
렌더링은 리스크가 아니다. 실제 시간을 잡아먹는 곳:
1. **네트워킹 안정성** — 재접속·호스트 마이그레이션·버전 동기화 엣지케이스.
2. **음성 지연/품질** — 대화 자연스러움의 핵심. AEC/노이즈/리전 튜닝.
3. **모더레이션 + 신고 백엔드** — 없으면 출시 불가.
4. **법무·컴플라이언스** — 개인정보 문서·PIPA/GDPR. 음성이라 가볍지 않다.
5. **온보딩 마찰** — 마이크 권한·장치·첫 입장 이탈.
6. **시선·립싱크 튜닝** — 어색하면 언캐니.
7. **DLC/결제 통합 + 소유권 게이팅** — 방 전체 격상 로직 검증.

## 23. 첫 개발자에게
- **스택:** Unity 6 + (NGO 또는 FishNet) + Steam Relay/Lobbies + Facepunch.Steamworks(또는 Steamworks.NET). 결제=Steam DLC/마이크로트랜잭션.

- **처음부터 지킬 것:** 참가자·방 오브젝트 추상화(§7·§20), 뮤트/개인볼륨 초기 삽입(나중에 끼워넣기 어려움), 지연을 상시 측정 지표로.
- **미루지 말 것:** 모더레이션·신고 백엔드·재접속·개인정보 문서. "데모는 되는데 출시가 안 되는" 전형적 이유.
